## 1. Обзор

Готовый пример с Next.js, FastAPI и PostgreSQL запускается командой `./examples/fullstack/demo up` из корня проекта. [Инструкция к fullstack-демо](../examples/fullstack/README.md)

**LottieX 0.1.0** раздаёт файлы и маршрутизирует запросы к вашим приложениям по HTTP/1.1. Для запуска по HTTP или с публичным HTTPS используйте [примеры для VM и Compose](../examples/reverse-proxy/README.md).

Основные возможности: GET и HEAD, индексы директорий, MIME-типы, IPv4/IPv6, проверка JSON-конфигурации, потоковая отправка файлов и завершение уже принятой работы при остановке.

Проект использует GNU Make, [cpp-httplib](https://github.com/yhirose/cpp-httplib) и [nlohmann/json](https://github.com/nlohmann/json). Зависимости включены в `includes/`; обычная сборка не требует интернета или отдельной загрузки библиотек.

## 2. Сборка и запуск

### Требования

| Инструмент | Для чего нужен |
| :--- | :--- |
| Linux | Сокеты, POSIX-сигналы и потоки |
| Компилятор и стандартная библиотека C++20 | Сборка; используются `std::jthread`, `std::stop_token`, `std::osyncstream` |
| GNU Make | Управление сборкой |
| Python 3 | Только запуск tests |
| curl | Только примеры запросов ниже |

### Установка одной командой

Без Git (нужны curl и tar):

```bash
curl -fsSL https://raw.githubusercontent.com/thekeny/LottieX/master/install.sh | bash
```

Или из корня проекта:

```bash
./install.sh
lttx check
lttx run
```

Скрипт сам выполняет release-сборку и устанавливает `lttx` в `~/.local/bin`, без `sudo`. При запуске через curl или вне репозитория он скачивает архив исходников с GitHub во временный каталог и удаляет его при завершении. Установка из локального репозитория работает без интернета. GNU Make и компилятор C++20 должны быть установлены заранее. Если каталог отсутствует в `PATH`, скрипт выведет команду для добавления — выполните её в текущем терминале и добавьте в настройки своей оболочки.

Другой каталог установки: `./install.sh --prefix /абсолютный/путь` или переменная `PREFIX`. Исполняемый файл попадёт в подкаталог `bin/`. Для обновления повторите установку; для удаления удалите установленный файл `bin/lttx`.

Команда `lttx` доступна из любой директории. Для `run` и `check` нужен `lottiex.json` в текущей директории либо аргумент `--config /путь/к/lottiex.json`. Установщик не копирует конфигурацию и файлы сайта.

Установка через curl с выбором каталога:

```bash
curl -fsSL https://raw.githubusercontent.com/thekeny/LottieX/master/install.sh | bash -s -- --prefix "$HOME/.local"
```

### Сборка без установки

```bash
make release
./build/lttx check
./build/lttx run
```

Откройте [http://127.0.0.1:8080](http://127.0.0.1:8080). Должна появиться страница **LottieX is running.** из `public/index.html`. По умолчанию сервер доступен на всех IPv4-интерфейсах (`0.0.0.0:8080`).

Остановка: **Ctrl+C** или SIGTERM процессу сервера.

### Режимы сборки

```bash
make release          # -O2 -DNDEBUG
make debug            # -O0 -g
make release CXX=g++  # явный выбор компилятора
make clean            # удалить объектные файлы и build/lttx
```

`make` без цели запускает release-сборку. Объектные файлы хранятся в `build/release/` и `build/debug/`, но исполняемый файл у обоих режимов один: `build/lttx`. Последняя сборка определяет его режим.

## 3. Справочник CLI

```text
lttx run [--config PATH]
lttx check [--config PATH]
lttx version
lttx help
```

| Команда | Поведение |
| :--- | :--- |
| `run` | Загрузить конфигурацию, привязать сокет и запустить сервер |
| `check` | Прочитать JSON, проверить поля и статический корень; вывести `Configuration OK` |
| `version` | Вывести `LottieX 0.1.0` |
| `help` | Вывести справку; используется и при запуске без аргументов |

`--config PATH` доступен только для `run` и `check`. Без него ищется `lottiex.json` в текущей рабочей директории. Относительный `PATH` также отсчитывается от рабочей директории.

```bash
lttx check --config /srv/demo/lottiex.json
lttx run --config /srv/demo/lottiex.json
```

Успешное завершение CLI возвращает код `0`; ошибка — `1` и сообщение `lttx: ...` в stderr. `check` не открывает слушающий сокет и не проверяет, свободен ли порт.

## 4. Конфигурация

Пример [`lottiex.json`](../lottiex.json), поставляемый с проектом:

```json
{
  "server": {
    "host": "0.0.0.0",
    "port": 8080
  },
  "static": {
    "enabled": true,
    "root": "./public",
    "index": "index.html"
  }
}
```

Все перечисленные поля обязательны. Значения в таблице — из примера, а не значения, автоматически подставляемые при пропуске поля. Используйте обычный JSON без комментариев и завершающих запятых.

| Поле | Тип | В примере | Правила |
| :--- | :--- | :--- | :--- |
| `server.host` | string | `"0.0.0.0"` | Числовой IPv4/IPv6-адрес; имена хостов не принимаются |
| `server.port` | integer | `8080` | От `1` до `65535` |
| `static.enabled` | boolean | `true` | Включить или отключить раздачу файлов |
| `static.root` | string | `"./public"` | Непустой путь; при включённой раздаче должен существовать и быть директорией |
| `static.index` | string | `"index.html"` | Непустой относительный путь без компонентов `..` |

### Обратный прокси

Добавьте необязательные секции `upstreams` и `routes`. В `upstreams` имя сервиса сопоставляется с HTTP-адресом, например `"api": "http://backend:8000"`. В `routes` каждый маршрут задаёт `path`, `match` (`exact` или `prefix`) и `action` (`static` или `proxy`). Для `proxy` укажите имя `upstream`. Для префиксов кроме `/` можно задать `"strip_prefix": true`.

Точное совпадение имеет приоритет, затем выбирается самый длинный префикс по границе сегмента. `/api` совпадает с `/api/users`, а `/apix` выбирает свой маршрут. При отсутствии совпадения применяется статика. Сопоставление использует исходный экранированный путь. Query string пересылается без изменений.

`lttx check` проверяет конфиг без подключения к сервисам. Прокси принимает GET, HEAD, POST, PUT, PATCH, DELETE и OPTIONS. Тела запросов ограничены настройкой `server.max_body_bytes`, а ответы передаются блоками по мере получения. [Поля и допустимые значения](proxy.md) · [Готовый запуск по HTTP и HTTPS](../examples/reverse-proxy/README.md)

### Адрес прослушивания

| Адрес | Назначение |
| :--- | :--- |
| `127.0.0.1` | Доступ только через IPv4 loopback |
| `0.0.0.0` | Все IPv4-интерфейсы |
| `::1` | IPv6 loopback; в браузере используйте `http://[::1]:8080/` |
| `::` | IPv6 wildcard; доступность IPv4 зависит от настроек ОС |

`localhost` в `server.host` не допускается. IPv6 записывается в JSON без квадратных скобок: `"host": "::1"`.

### Относительные пути

`static.root` разрешается относительно **директории файла конфигурации**. Если конфигурация находится в `/srv/demo/lottiex.json`, то `"root": "./public"` указывает на `/srv/demo/public`, независимо от директории запуска процесса.

При `static.enabled: false` существование директории не проверяется, но остальные поля и их формат всё равно обязательны. GET и HEAD на статических маршрутах возвращают 404.

Изменения конфигурации применяются после перезапуска. Команда `check` не проверяет наличие каждого файла или индексной страницы.

## 5. Раздача файлов и HTTP

### Соответствие URL и файлов

При корне `public/` и индексе `index.html`:

| URL | Файл или результат |
| :--- | :--- |
| `/` | `public/index.html` |
| `/styles.css` | `public/styles.css` |
| `/images/logo.png` | `public/images/logo.png` |
| `/guide/` | `public/guide/index.html` |
| `/guide` | Индекс той же директории, если `guide` — директория |
| `/styles.css?v=1` | `public/styles.css`; query string не участвует в поиске |
| `/missing` | 404, если такого файла или директории нет |

Индекс добавляется только для директории. Нет листинга файлов и SPA fallback на корневой `index.html`.

Путь декодируется из исходного URL ровно один раз. Например, `/%252e%252e/file.txt` обращается к буквальной директории `%2e%2e`, а `/%2e%2e/file.txt` содержит `..` и отклоняется с 404. Символьные ссылки допускаются, пока конечный канонический путь остаётся внутри статического корня; проверка повторяется после добавления индекса.

### Методы и ответы

| Ситуация | Ответ |
| :--- | :--- |
| GET существующего файла | `200`, содержимое файла |
| HEAD существующего файла | `200`, тот же `Content-Length`, что у GET, без тела |
| Нет файла или индекса, раздача выключена, выход за корень | `404` |
| Другие распознаваемые методы: POST, PUT, DELETE, OPTIONS, PATCH, TRACE | `405`, `Allow: GET, HEAD` |
| Некорректный путь или неподходящий формат запроса | `400` |
| Ошибка открытия существующего файла или файловой системы | `500` |

Сервер ожидает HTTP/1.1 с одним непустым заголовком `Host`. Статические маршруты отклоняют запросы с `Transfer-Encoding` или `Content-Length`, отличным от `0`. Пути со скрытыми компонентами вроде `.env` возвращают 404. Проверка формата запроса выполняется раньше проверки метода, поэтому некорректный запрос может получить 400 вместо 405.

Ответы содержат `Server: LottieX` и `Connection: close`. После каждого ответа соединение закрывается.

### MIME-типы

Регистр расширения не важен.

| Расширение | Content-Type |
| :--- | :--- |
| `.html`, `.htm` | `text/html; charset=utf-8` |
| `.css` | `text/css; charset=utf-8` |
| `.js` | `text/javascript; charset=utf-8` |
| `.json` | `application/json` |
| `.png` | `image/png` |
| `.jpg`, `.jpeg` | `image/jpeg` |
| `.svg` | `image/svg+xml` |
| `.txt` | `text/plain; charset=utf-8` |
| `.ico` | `image/x-icon` |
| Остальные | `application/octet-stream` |

### Примеры запросов

При запущенном сервере, из другого терминала:

```bash
curl -i http://127.0.0.1:8080/
curl -I http://127.0.0.1:8080/
curl -i http://127.0.0.1:8080/missing
curl -i -X POST http://127.0.0.1:8080/
curl --path-as-is -i http://127.0.0.1:8080/../outside.txt
```

Ожидаемые статусы: `200`, `200`, `404`, `405`, `404`.

## 6. Архитектура и ограничения

Путь запроса: **cpp-httplib → очередь соединений → проверка HTTP и пути → маршрут → файл или upstream → content provider → ответ**.

| Параметр | Значение |
| :--- | :--- |
| Сетевой слой | cpp-httplib, блокирующий ввод-вывод |
| Рабочие потоки | 8 |
| Максимум ожидающих соединений в очереди | 64 |
| Блок чтения файла | До 64 КиБ |
| Таймаут чтения / записи | По 30 секунд |
| Запросов на соединение | 1 |

В таблице приведены значения по умолчанию. Лимиты сервера настраиваются через JSON. Файлы отправляются через content provider без загрузки всего содержимого в строку ответа. При переполнении очереди новое соединение закрывается; HTTP-ответ 503 не гарантируется.

SIGINT и SIGTERM обрабатывает отдельный поток ожидания сигналов. Сервер прекращает ставить новые соединения в очередь и завершает уже принятую работу, включая ожидающие соединения и незавершённые заголовки запросов. Затем закрывается слушающий сокет. При наличии upstream активные сокеты закрываются по истечении `server.drain_seconds`. При раздаче только статики действуют сетевые таймауты.

За TLS в публичном примере отвечает Caddy. Обработка HTTP, включая потоковые SSR и SSE, остаётся в LottieX.

## 7. Проверка и диагностика

### Smoke-тесты

```bash
make release
python3 tests/smoke.py
python3 tests/proxy.py
make debug
python3 tests/smoke.py
python3 tests/proxy.py
make release
```

Тесты запускают реальные локальные серверы, создают временные файлы и символьные ссылки. Проверяются CLI, конфигурация, GET/HEAD, MIME-типы, большие и пустые файлы, индексы, пути, параллельные запросы, занятый порт и остановка. Проверка IPv6 пропускается только при недоступности IPv6 loopback. Последняя команда оставляет release-версию `build/lttx`.

### Частые проблемы

| Сообщение или симптом | Что проверить |
| :--- | :--- |
| `Cannot open configuration` | Путь после `--config`; без него — наличие `lottiex.json` в рабочей директории |
| `Invalid configuration field: ...` | Сверить указанное поле с описанием конфигурации |
| 502 или 504 | Проверить адрес сервиса или таймаут по [инструкции запуска](../examples/reverse-proxy/README.md#диагностика) |
| `Cannot listen on ...` | Адрес существует на машине, порт свободен, у процесса есть права на привязку |
| 404 для `/` | Раздача включена, в `static.root` есть файл `static.index` |
| 404 для существующего файла | Корень отсчитан от конфигурации, путь и регистр имени верны, ссылка остаётся внутри корня |
| Ошибка сборки из-за зависимостей | Восстановить `includes/cpp-httplib/` и `includes/nlohmann/` из полной копии проекта |

В репозитории нет `scripts/vendor.py`; запускать его для сборки не требуется. Ошибки отсутствующих полей и синтаксиса JSON могут выводиться непосредственно от nlohmann/json.

При запуске сервер печатает версию и адрес. Журнал запросов содержит время UTC, ID запроса, метод, путь без query string, статус, длительность в микросекундах, размер тела ответа и имя upstream. Ошибки upstream попадают в stderr с тем же ID запроса.

## 8. Структура проекта и лицензия

```text
LottieX/
├── Makefile
├── lottiex.json
├── src/main.cpp                 # команды lttx
├── includes/
│   ├── lottiex/
│   │   ├── LottieX.hpp           # общий заголовок
│   │   ├── config.hpp           # загрузка и проверка JSON
│   │   ├── http.hpp             # версия, URL-декодирование, MIME
│   │   └── server.hpp           # маршрутизация, очередь и остановка
│   ├── cpp-httplib/             # библиотека и лицензия
│   └── nlohmann/                # библиотека и лицензия
├── public/                      # статика и логотип
├── docs/                        # ru.md и en.md
└── tests/                       # интеграционные тесты статики и прокси
```

Для включения заголовков приложения используется `<lottiex/LottieX.hpp>` и путь поиска `-Iincludes`. Регистр имени важен на Linux.
